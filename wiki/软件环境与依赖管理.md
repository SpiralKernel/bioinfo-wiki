# 软件环境与依赖管理

> 更新：2026-10-14；状态：可用；验证范围：文档核对；操作示例未在本机运行。

一个可复现环境需要记录软件版本、依赖、平台及参考数据，只有环境名称并不足够。

## 环境解决什么问题

不同项目可能需要不同的Python、R和系统库。独立环境减少依赖冲突；容器封装更多运行依赖；它们都不能自动固定输入数据、参考数据库或分析参数。首先查看[可复现分析与工作流管理](https://github.com/SpiralKernel/bioinfo-wiki/wiki/%E5%8F%AF%E5%A4%8D%E7%8E%B0%E5%88%86%E6%9E%90%E4%B8%8E%E5%B7%A5%E4%BD%9C%E6%B5%81%E7%AE%A1%E7%90%86)中需要保存的材料。

Conda按项目组织包；R项目可使用renv；容器在服务器上常通过Apptainer等运行。具体方案受平台和管理员配置限制。不要把一种工具的安装命令误当作所有平台都可直接复制的流程。

## Conda练习结构

以下仅展示环境管理顺序，尚未在本机执行：

```bash
conda create -n bioinfo-demo python=3.12
conda activate bioinfo-demo
python --version
conda env export --from-history > environment.intent.yml
conda list --explicit > environment.platform-lock.txt
```

`--from-history`偏向记录主动请求的包，便于理解需求；explicit文件更接近当前平台的精确包清单，不保证跨操作系统通用。实际包来源、构建与平台也要保存。大型生信流程还应固定工作流版本、容器标签或digest、参考资源版本。

## 检查与失败处理

用 `command -v python` 确认实际执行文件，记录版本输出；激活环境后仍找不到程序时，先查当前shell、PATH和安装是否成功。出现依赖冲突时保留原环境和错误日志，在新环境中缩小问题；不要在一个共享环境中反复升级所有包。

程序存在不代表依赖完整。先运行官方小测试，再执行正式数据；结果异常时结合[日志排错与最小复现](https://github.com/SpiralKernel/bioinfo-wiki/wiki/%E6%97%A5%E5%BF%97%E6%8E%92%E9%94%99%E4%B8%8E%E6%9C%80%E5%B0%8F%E5%A4%8D%E7%8E%B0)定位。深入：[Conda环境管理](https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html)、[renv入门](https://rstudio.github.io/renv/articles/renv.html)、[Apptainer文档](https://apptainer.org/docs/user/main/)。
