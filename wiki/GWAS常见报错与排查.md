# GWAS常见报错与排查

> 更新：2026-10-13；状态：可用；验证范围：实际案例的格式与方向问题已核对；症状表其他路径按官方文档整理，未逐项复现。

先把失败定位到身份、格式、模型、数值或资源，再用最小例子验证修复。

## 按症状定位

| 症状 | 先检查 | 处理与复核 |
|---|---|---|
| 几乎没有样本进入分析 | FID/IID或taxa、前导零、缺失标签、选错性状 | 导出各表ID及交集，核对排除名单 |
| 协变量无效或矩阵奇异 | 常数列、重复PC、全套分类指示列与截距 | 核对列含义与矩阵秩，按设计修复编码 |
| K出现NaN或不可逆 | 单态位点、错误编码、样本顺序及矩阵来源 | 检查过滤与K定义，不直接替换NaN为0 |
| 输出为空或只有标题 | 位点过滤、MAC、实际染色体、模型失败 | 查看每步计数与日志，区分无可检验位点与未显著 |
| PLINK ERRCODE非`.` | 具体失败代码及对应位点 | 按手册检查分离、共线、低计数等，不统一改成P=1 |
| REGENIE找不到预测 | Step 1是否成功、pred.list路径、性状对应 | 检查列表与被引用文件，不用ignore-pred掩盖缺失 |
| SAIGE模型或方差比不匹配 | 拟合版本、样本、完整/稀疏模式 | 按同一轮拟合重建对应Step 2输入 |
| GCTA找不到GRM | 前缀、三件套、ID文件、模块选择 | 保留矩阵与ID整体，检查读入后的个体数 |
| 程序完成但β方向相反 | 计数等位基因、标签、性状变换 | 先做[GWAS结果字段与等位基因统一](https://github.com/SpiralKernel/bioinfo-wiki/wiki/GWAS%E7%BB%93%E6%9E%9C%E5%AD%97%E6%AE%B5%E4%B8%8E%E7%AD%89%E4%BD%8D%E5%9F%BA%E5%9B%A0%E7%BB%9F%E4%B8%80) |
| 把REGENIE LOG10P画坏 | 是否将−log10(P)再次取对数 | 明确字段表示，再计算或直接使用 |
| 任务被杀或未生成完整结果 | 调度器OOM、时间、磁盘与线程 | 看资源记录及实际退出状态，再有依据调整 |

## 怎样构造最小复现

保留原输入，选少量能够重现问题的样本和位点；同时保持必要的病例计数、表型变异和协变量秩。过度缩小到所有人性状相同或只有一类病例，会引入新的错误。

保存版本、完整命令、失败日志与预期行为。一次改变一个因素，用同一小例子检验；修复格式后还应核对样本数、效应方向和结果字段。

## 运行完成后的异常也要查

QQ严重偏离、极端效应、异常SE、样本量逐位点变化或组装不一致，可能是输入或模型问题。不要通过挑选更小的P值、删除不喜欢的位点或反复添加PC把图调成目标形状。

本轮确实遇到了扩展FAM的兼容、效应方向对齐及软件版本接口差别，并通过独立转换与同模型对照验证。其他症状表是按接口组织的诊断入口，不代表本机复现过每种故障。
